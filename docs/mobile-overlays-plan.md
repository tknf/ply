# スマホのオーバーレイをボトムシートへ統一する計画

状態：方針合意済み・未実装（2026年9月15日）。コンポーネント確認と切り離して後続で実装する。

## 方針

- スマホの独立した操作・確認・設定は、原則として下から出るボトムシートにする。
- 表示位置・幅・高さ・余白・動きはCSSで制御する。JavaScriptで画面寸法を監視して同じレイアウトを再計算する実装は避ける。
- 開閉、フォーカス、背景の操作制限、階層移動はHTMLの標準機能と最小限のcontrollerで扱う。CSSだけでモーダルの意味や操作まで切り替えられるとは扱わない。
- 矢印は操作アイコンより小さくする。項目全体のタップ領域は維持する。この調整も未実装。

## 対象

| 内容                           | 狭い画面での方針                             |
| ------------------------------ | -------------------------------------------- |
| Dialog、操作一覧のDropdownMenu | 内容量に合う高さのボトムシート               |
| 絞り込み・複数選択・日付選択   | 必要に応じて適用／キャンセルを持つシート     |
| 多段サブメニュー               | 同じシート内で次の一覧へ進む。「戻る」を置く |
| 長いフォーム・複雑な編集       | 全画面に近いシート、または専用ページ         |
| 入力候補・対象に密着した補足   | 原則として入力欄や対象の近くに残す           |

## 実装順

1. **矢印を調整する。** 共通アイコンを一律縮小せず、開閉・階層を示す矢印のサイズを分ける。
2. **DialogでCSSの表示切り替えを作る。** 広い画面では既存のダイアログ、狭い画面では下端へ配置する。標準の`dialog`を優先し、共通化は実際に共有するスタイルから始める。
3. **DropdownMenuへ適用する。** 操作一覧、選択状態、選択イベントを維持し、サブメニューは一枚のシート内で切り替える。現在の透明レイヤーとの重複を整理し、外側クリックで背後を操作しない方針を保つ。
4. **他の対象へ展開する。** 日付選択・絞り込みなどへ必要な範囲で適用し、カタログに広幅・狭幅の対応例を揃える。

## 着手時に決める境界

- レイアウトの切り替えはCSSの画面幅を基準とし、端末名では判定しない。具体的な閾値は既存レイアウトと内容量で決める。
- DropdownMenuは現在`role="menu"`と矢印キー操作を持つ。シート内でもその操作を維持するか、通常のボタンを並べたダイアログへ変更するかを決める。見た目だけを変えて役割・フォーカスの規則を不整合にしない。
- 表示幅をまたいでも、選択値・入力値・開いている階層・フォーカスを失わない。DOMの重複生成は避ける。役割やモーダル状態の切り替えが必要な場合だけJavaScriptで同期する。
- シートの高さは内容に追従させ、表示領域を超える場合は内部をスクロールさせる。ソフトウェアキーボード、safe area、横向き表示を考慮する。

## 完了条件

- 狭幅・広幅、一行・長文・大量項目、多段階層で操作できる。
- モーダル表示中は背景をポインターでもキーボードでも操作できず、閉じると適切な位置へフォーカスが戻る。
- 閉じる／キャンセルと階層の「戻る」を用意する。スワイプだけを必須の操作にしない。
- タッチ、外付けキーボード、スクリーンリーダーで役割と操作が一致する。
- [文字位置の規約](control-text-alignment.md)と上揃えの方針を維持する。
- 静的検査と表示・操作の確認を分けて記録する。現在はComputer use・Playwright実行禁止のため、実ブラウザの検証は明示的に許可された場合に実施する。未実施の確認を完了扱いにしない。
