# コンポーネントのtransitionを統一する計画

状態：未実装。2026年9月15日、ユーザーの指摘を受け、各コンポーネントの作り直し後の仕上げとして実施する。

## 後でまとめる理由

現状は共通CSSの`box-shadow`だけのtransitionと、部品固有の背景色・枠線・移動のtransitionが混在している。Buttonにも共通のtransition宣言は適用されるが、primaryの背景色変化は対象外で、部品によって反応が違って見える。

作り直し中はホバーや選択状態の表現自体が変わるため、各部品の状態表現が固まってから横断的に揃える。全コンポーネントの確認を終えた後、この作業を仕上げの必須項目として実施する。スマホのボトムシート計画の完了は着手条件にしない。

## 方針

- 同じ役割の状態変化には同じ時間・イージングを使う。基準は既存の`--ply-duration: 150ms`と`ease`とし、最終確認で一括調整する。
- Button／ActionLink、Disclosure、メニュー、Tabs、フォーム部品、日付選択、一覧操作などのhover・active・選択状態を棚卸しする。通常・primary・danger・linkなどの変種とdisabledも対象にする。
- 色の変化は`color`・`background-color`・`border-color`・必要な`box-shadow`を明示する。`transition: all`は使わない。変化しないプロパティを全要素に機械的に追加しない。
- 共通指定と部品固有指定の上書きを整理し、同じ操作で反応速度が変わる状態をなくす。フォーカスリングの表示は遅らせない。
- 矢印、Switch、Range、保存状態、読み込み表示などの動きも確認する。文字位置やレイアウト寸法の不要なアニメーションは追加しない。Disclosureの本文の高さアニメーションは、この統一のためには追加しない。
- `prefers-reduced-motion: reduce`では装飾的なtransition・animationを停止する。既存の時間トークン0ms化とLoadingの`animation: none`を確認し、固定時間や独自指定による漏れをなくす。状態変化と読み込み中であることは静止表示でも伝える。
- 後続のボトムシート実装もこの方針に従う。

## 実施順と完了条件

1. `src/css`とカタログのtransition・animation・状態別指定を一覧化し、変更するプロパティと所有箇所を確認する。
2. 共通ルールと必要な部品固有の指定を修正する。動きを止める設定を含む比較用の作例を揃える。
3. `vp run check`、必要な回帰テスト、`vp run build`を実行する。時間の直書きやreduced-motionの適用漏れを検出できる静的検査を追加する。
4. 通常設定とreduced-motionの両方で、マウス・キーボード操作、押下・解除、開閉、連続操作を確認する。通常時は同じ役割の反応が揃い、reduce時は状態が遅延なく伝わることを確かめる。

Computer use・ブラウザ操作・Playwright実行は禁止されている。禁止が続く場合はソース検査まで進め、実画面の確認は未実施として区別する。静的検査の成功だけで動きの統一を確認済みにしない。
