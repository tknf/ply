# 統一性の棚卸し（2026年9月26日）

`/review/components`の全72コンポーネントを1280pxで開き、枠・面・影・文字を持つ要素4,665個の計算値を集めた。コンポーネント単体の見た目ではなく、同じ役割の要素が同じ値になっているかを見る。

## 事実

### 形（角丸）

| 値                 | 使っているコンポーネント数 | 主な要素                                                  |
| ------------------ | -------------------------- | --------------------------------------------------------- |
| ピル               | 52                         | Button全て、Tag、Badge、検索・select・候補の入力          |
| 8px                | 26（ほかに7.99pxが12）     | 一行入力、複数行入力、一覧の枠、Notice                    |
| 12px               | 6                          | 作業面、Card                                              |
| 50%                | 37                         | Avatar、Disclosureの印、アイコンだけのButton              |
| 3px・4px・6px・9px | 10                         | Calendarの予定、チェックボックス、Keycap、ColorPickerの面 |

- **Fieldの中で形が混ざっている。** 一行入力と複数行入力は8px、selectと検索と候補の入力はピル。同じフォームに並ぶと、規則ではなく気まぐれに見える。
- 3px・4px・6px・9pxは、それぞれのコンポーネントの都合で決めた値で、規則がない。

### 枠の色

- 通常の枠は`--ply-border`の1色だが、Disclosureの印（カタログ全体で使う）だけ青みの枠を持ち、全ページに出ている。
- 2pxの枠が4種類ある（Timelineの印の青・緑・点線、Loading）。太枠の語彙（今・編集中）とは関係のない使い方が混ざっている。

### 影

- 6層の影（操作と面）、2層の影（入力の内側）、1層の影、8層の影（ColorPicker）の4種類。影の段が役割で決まっていない。

### 文字

- 大きさと太さの組が31通りある。主な組は13px/400、14px/400、14px/600、16px/400、16px/600。
- 太さ500はCalendarだけが使っている（240か所）。
- 10〜12pxの文字は、ほぼCalendarだけ。
- 余白は、枠を持つ要素だけで65通りある。

## 何が足りなかったか

形・影・状態を属性ごとに決め、部品ごとに当てはめた。フォームや一覧のように部品が並ぶ画面で確かめていないため、規則どうしがぶつかっても気づけなかった。「選ぶ欄はピル、書く欄は角」は意味としては分けたが、同じフォームの中で形が混ざる。

## 規則の案

部品の意味ではなく、**同じ種類の部品は同じ形**を先に守る。

1. **形は3種類だけ。** 同じ種類の中では混ぜない。
   - 押す物（Button、Tag、Badge、FilterBar、ToggleGroup、Pagination）：ピル
   - 書く・選ぶ欄（一行、複数行、select、検索、候補、日付、時刻）：全て同じ角。
     - 案A：8pxの角（HEYと同じ。欄は小さく丸く、ボタンだけピル）
     - 案B：一行の欄もピル、複数行は一行の欄の高さの半分（16px）の角。欄全体を丸い言葉づかいにそろえる
   - 面（作業面、Card、メニュー、ダイアログ）：12px
   - 円は「人・印」だけ（Avatar、アイコンだけのButton、今日・状態の印）。
2. **文字は5段×2つの太さ。** 12/13/14/16/見出しの段と、400・600。700はページ見出しだけ。500は使わない。
3. **影は3段。** 手に取れる物（Card、Boardの項目）、押す物（Button）、浮かぶ物（メニュー、ダイアログ、Toast）。入力の内側の影は欄の種類で一つ。
4. **枠は2色と状態の色。** 普通の線（`--ply-border`）、書く・選ぶ欄の線、状態の色（青・赤）。太枠（2px）は「今・編集中」だけ。
5. **余白は段から選ぶ。** 部品の内側は`--ply-space-*`とButtonの寸法の組から選び、部品ごとの端数を作らない。

## 手触りの候補

整理だけでは「よくあるデザインシステム」から出られない。ミシン目・波線・斜線と同じく、紙と文具の振る舞いから意味を決め、一つの部品に一つまでにする。

| 候補                                   | 意味                   | 使う場所の案                                     |
| -------------------------------------- | ---------------------- | ------------------------------------------------ |
| ゴム印（少し傾いた枠の印）             | 確定した・承認された   | 完了したタスク、承認済みの状態、Stepsの完了      |
| 蛍光ペン（文字の裏に引く少し傾いた帯） | 見つけた・目印         | 検索の一致、`mark`、引用の強調                   |
| ペンの丸囲み（手描きの楕円）           | 今日・ここに注目       | Calendarの今日、未読件数                         |
| 赤ペンの波線                           | 直すところ             | エラーの欄と、エラー文の該当箇所                 |
| インデックスのつまみ                   | ここから別の紙         | Tabs（今のつまみが下の紙とつながる）、Cardの分類 |
| マスキングテープ                       | 留めてある             | 固定したメモやCard                               |
| 付箋の折れ角                           | 手元のメモ・あとで見る | メモ、下書き、コメント                           |
| ペンで描くチェック                     | やり終えた             | TaskListのチェック（線が描かれる短い動き）       |
| クリップ                               | 添付されている         | 添付ファイルのあるMessageやCard                  |

## 進め方

1. 規則の案（特に欄の形の案A・案B）と手触りの候補を決める。
2. 決めた規則で、フォーム・一覧・ボード・メールを組んだ見本ページを作り、見て合意する。
3. 合意した見本に合わせて、コンポーネントを一つずつ直す。棚卸しを撮り直し、同じ種類の部品で値が一つになっていることを確かめる。
