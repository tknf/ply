# Plyの設計方針

Plyは、メール、CRM、プロジェクト、文書、財務、チャットを組み立てるためのコンポーネントライブラリ。特定の管理画面やタスク管理アプリを成果物の代わりにしない。

目標はHEY・Fizzyのゆとりのある大きさと余白、Basecamp・HEYの中央で仕事に向き合う構成、その中で押す・選ぶ・片付ける操作が気持ちよく続くこと。細部の規則はClickUpからも学ぶ。サイドバーは採用しない。上部中央のCommandMenuを独立したコンポーネントとして持つ。

## 立体感と手触り、アプリが足す表情

2026年9月26〜27日に、全コンポーネントを「重ねた紙と文具」（切手・切符・付箋・荷札・ゴム印・ミシン目など）で作り直した。ユーザーの評価は「個人的には好きだが、HEYと違って悪目立ちする」。HEY・Fizzyと比べると、比喩を名前と振る舞いでなく形に描いたこと、器の文字が中身の題名より強くなったこと、同じ強さの飾りが全ての行に常にあったことが原因だった（[比較](audits/20260927-hey-fizzy-comparison.md)）。この版は`mast1ff/ply-playground`の同じ名前のブランチに保管している。

Plyは文具の形の装飾を持たない。ゴム印・波線・ミシン目のような表情は、アプリごとに意味と場所を決めて足すものとする。Plyが持つのは次の二つ。

- **立体感**：紙の影（`--ply-shadow-paper`、持ち上げた紙は`-lift`、浮かぶ物は`--ply-shadow-menu`）、押す物の縦の陰影（`--ply-fill-control`）、主操作と「ここを見て」の面の135度のグラデーション、押した時に影が内側へ移る動き。
- **手触り**：出来事の瞬間の短い動き。確定・完了でペンが書くチェック、運ぶ紙の傾きと持ち上がる影。常にある飾りにはしない。
- **出入り**：浮かぶ物は、どこから来てどこへ戻るかを動きで示す。Dialog・Popover・HoverCard・Tooltip・Toast・DropdownMenu・CommandMenu・DatePickerの出入りはoverlay.cssの一か所だけに定義し、各コンポーネントは支点（transform-origin）だけを決める。HEYのpop-openのように支点から0.85倍で現れて一瞬膨らんでから約0.17秒で収まり、閉じる時は約0.1秒で縮みながら消える。Toastと画面の下に付くDialogは下から差し出す。Disclosureは高さを伸ばしながら中身を出す。

状態を示す一般的な線と模様は、装飾ではなく表示として残す。使えない枠の斜線、「これから」のStepsとTimelineの破線、仮の予定、ファイルのドロップ先や空の列の「ここに置ける」細い破線、「今」を示す太枠。

アプリが表情を足す時は、HEY・Fizzyと同じく、出来事の瞬間か、一画面に一つか二つの場所に置く。一覧の全ての行や小さな部品に同じ強さの飾りを付けない。

### 横断の規則

コンポーネントごとの都合で見た目を決めない。同じ意味には、どのコンポーネントでも同じ構造と同じディテールを使う（[HEY](references/hey-app-20260926/README.md)、[Fizzy](references/fizzy-20260926/README.md)の規則の作り方）。

1. **形**：同じ種類の部品は同じ形。押す物はピル。紙（作業面・Card・Boardの項目・Composer・メニュー・ダイアログ）は`--ply-radius-surface`（16px）、作業面の中の面（Navigationの板、ColorPickerの面、説明付きの選択肢）は`--ply-radius-field`（12px）、書く・選ぶ欄（Input、Select、InputGroup）はHEYの欄（6.6px）に寄せた`--ply-radius-control`（8px）、面の内側の行も同心の`--ply-radius-control`、小さな札（チェックボックス・Keycap・Calendarの予定）は`--ply-radius-mark`（4px）、円は人と印だけ。角丸と1pxの枠線を組み合わせた箱を作らない。Buttonは主・控えめ・危険の違いを塗りの色で出し、形では分けない。主操作は青、危険は赤で135度に塗り、控えめな操作は白い縦の陰影にする。影の付き方と、指を載せた時・押した時の変化は三つとも同じ。
2. **紙と情報と欄**：
   - 紙（手に取れる物・書く物・浮かぶ物）は枠線を持たず、紙の影（`--ply-shadow-paper`、浮かぶ物は`--ply-shadow-menu`）で見せる。
   - 作業面に書かれた情報は枠で囲まない。一覧（DataList、ActionList、TaskList、Comparison）は始まりと終わりの罫線と、行の間の淡い罫線だけ。ActionListの行の線は、HEYの人の一覧やNavigationと同じく題名の書き始めから引く。連絡の一覧（MessageList）はHEYのメールの一覧と同じく罫線を引かず、行間で区切って、指を載せた行だけ角丸の淡い面にする。Noticeは役割の色の面だけ。
   - 枠線を持つのは、書く・選ぶ欄と、意味のある線（Gridの罫など）だけ。選択肢の束（ChoiceGroup）は枠で囲まず、Fieldと同じくラベルの下に並べる。
   - 欄はHEYの欄と同じく1pxの枠を持ち、Plyの個性として内側の浅い影（`--ply-shadow-input`）で沈める。フォーカスは青い縁の外に淡い青の2pxの輪（`--ply-focus-ring`）を広げる。Switch・チェックボックス・ラジオも同じ輪にする。
3. **グラデーション**：二つの用途だけ。押す物（Button、選択肢、ページ送り、持ち手）には、分かるか分からないかくらいの縦の陰影（`--ply-fill-control`）で手触りを付ける。「ここを見て」の面（Notice、ErrorSummary、一括操作の帯、主操作）には、役割の色からその淡い対への135度（`--ply-emphasis-*`、`--ply-fill-primary`）を使う。一覧・本文・情報の面は平ら。
4. **状態**：
   - 現在地（今いる場所）は、インクの太字と青い印。横の並び（Tabsなど）は下に2pxの印を置く。縦並びのナビゲーション（Navigation）は、HEYのaction-groupと同じく面を塗らず、行の終わりの側に青いチェックを置く。一覧の中で隣に開いている行（DataList、MessageList）は、淡い青の面と開始側の2pxの印。番号で並ぶ物（Pagination、Steps）だけは塗った円。パンくずの最後は並びの終わりなので太字だけにする。MessageListは太字を未読に使うため、現在地は印だけにする。
   - オン（切り替えた状態）は青い塗り。
   - 選択中（選んだ値）は淡い青の面。
5. **まとまりの見出し**：太字の名前、件数、終わりの側の操作の順。件数は名前の直後に置く。Section、Boardの列、目次、Comparison、FieldGroupで同じ形にする。続く一覧や表が罫線を持つので、見出しから線は伸ばさない。線を伸ばすのは、画面に一つの中央揃えのPageHeaderと、線そのものが役目のDividerだけ。
6. **項目の構造**：一覧の項目は「題名（太字）・補足・メタ情報」の順で、メタ情報は小さな文字を点で区切る。状態のBadgeと操作は末端に寄せる。Card、DataList、ActionList、MessageList、BoardのItemで同じ順にする。
7. **選んだ候補**：選んだ候補のチップは、どの入力でも入力の下に置く。

## 参照と採用値

[保存した実画面と測定値](references/measurements-20260915.md)を基準にする。元の画面で測った値と、Plyで採った値を分けて記録する。Button以外の造形の受け入れを、測定やテストの成功から推定しない。

| 操作・入力ラベル       | 13.5→14px（`--ply-label`）、ラベルは600                                                             | Fizzy 14.25px・600、HEY 15.4〜17.6px・500            |
| 本文・一覧と項目の題名 | 15→16px（`--ply-body`）、題名は600                                                                  | Fizzy 16.15px、HEY 19.8px                            |
| 小見出し               | 20→22px（`--ply-section-title`）                                                                    | HEY 22px、Fizzy 20.9px                               |
| ページ見出し           | 28→36px（`--ply-title`）、画面幅に連続して追従                                                      | HEY 44px、Fizzy 28.5〜34.2px                         |

| 間隔                   | 補足4px、入力ラベル6px、関連要素8px、見出しと中身12px、まとまり24px、セクション32px                 | HEY 24.75px（基準の余白）、Fizzy 19px                |

見出しはHEYに寄せて大きくし、普通の文字はFizzyの操作と題名に合わせた（[実測](references/hey-fizzy-20260927/README.md)）。9月27日に一度、普通の文字もHEY寄り（本文18px・操作16px）にしたが、ユーザーの確認で普通の文字はFizzyくらいがよいと決めた。

文字に連動する値はrem・em・単位なし行高を使う。枠線の1pxを内寸へ二重加算しない。意味のない固定高で複数行を切らない。

## 形と触感

- 面・人物・分類・操作には別の形を与える。何でも同じ角丸のカードへ入れない。
- CommandMenuとNavigationの移動・操作の行は、共通の`--ply-radius-control`（既定8px）を使う。表示場所の違いだけでピル型と角丸矩形に分けない。
- 操作のメニュー（DropdownMenu）は、HEYのメニューと同じく白い紙ではなく青の面（`--ply-fill-menu`）に白い文字で出す。見落とされてはいけないToastも、知らせの種類の色（知らせは青、成功は緑、注意はアンバー、失敗は赤）で塗る。読み物や入力を載せるDialog・Popover・HoverCardは白い紙のままにする。
- Disclosureは控えめな矢印と名前だけにし、枠付きのつまみや中身の縦線は引かない。入れ子は字下げで示す。
- Buttonはピル。主操作と危険は役割の色の135度のグラデーションで塗り、控えめな操作はさりげない縦の陰影の面と枠にする。接地から遠方まで濃度を減らす影を使い、指を載せると影が広がり、押したときに影が内側へ移る。塗りの色は変えない。文字自体は動かさない。
- Dialog・Popover・HoverCard・Toastの閉じる操作は、青いアイコンだけのButton（28px、タッチでは44px）にし、紙の終わりの側の上の角から4pxはみ出させる。紙は切り取らず、本文だけをスクロールする。色で塗ったToastの上では白地に反転する。
- 狭い画面のタッチ操作のDialogは画面の下に付くシートにする。上端にハンドルを置き、ハンドルと見出しを下へ引くと閉じる。閉じる操作は見出しの行の終わりに置いて題名を隠さず、下端はホームバーの分も空ける。
- 操作以外の情報を影で浮かせない。Tagははっきりした役割の色の縁と文字のピル、Avatarは中間の濃さで塗った丸に濃いインクの太いイニシャル（HEYの人の円）、完了は小さなチェックで示す。ファイルの印は枠で囲まず、淡く塗った札に置く。
- 角丸は横断の規則1の四つだけ。部品ごとの端数（3px・6px・9pxなど）を作らない。
- Plyの造形上の目安として、定型のCardやButtonは上下より左右に少し広い余白を取る。縦に読む親の面は左右より上下を広くし、下端に操作が来る面は上より下を少し狭くする。
- 見出しから本文へ流れる面は上端をやや広く、下端をやや狭くする。ただし、内容と配置を見て調整し、固定比率にはしない。
- 同じ対象の題名と補足は近付ける。行ごとに大見出しや長い説明を繰り返さない。全てを太字にせず、未読・現在地・見出し・入力や値の名前など意味のある所に使う。
- 青を主操作に使い、緑・アンバー・コーラルを明示した分類や状態へ使う。業務名や人物名から勝手に色を割り当てない。色だけで状態を伝えない。
- チェックの短い変化、見つけやすい現在地、すぐ隣の次の操作で手触りを作る。常時動く飾りや無関係なイラストを仕事へ重ねない。

上記の余白比はPlyの設計仮説であり、研究で定まった普遍値ではない。[共通領域による群化](https://www.sciencedirect.com/science/article/pii/001002859290014S)と[余白による区分の補助](https://www.w3.org/WAI/WCAG2/supplemental/patterns/o3p10-whitespace/)を情報のまとまりに使う。一方、[視覚的な均衡と好みの実験](https://www.frontiersin.org/journals/psychology/articles/10.3389/fpsyg.2016.00335/full)から、単純な重心計算だけで好ましさを決めない。

## 文字位置

[文字位置の規約](control-text-alignment.md)をUI変更前に読む。共通フォントの89%／11%／0%の行メトリクスを保つ。Buttonはbutton.cssが文字・太さ・行高・上下余白を所有する。派生コンポーネントや子のspanから移動させない。

UI全体は同じローカル書体の組み合わせを使い、字間をnormalにする。読む本文は行高と行長で読みやすさを作る。Fontの追加配布は必要としない。

DropdownMenuは上揃え。一行時の中央は対称な上下余白から作り、説明が増えたら同じ上端から下へ伸ばす。DatePickerの月送り・クリアは共通Buttonの文字をそのまま使う。

## 構造と操作

- AppShellは上部中央の移動と中央の作業面。狭幅では左右の補助操作を別行へ移して中央を保つ。
- CommandMenuは背景を暗転しないnative popover。主要な入口と最近の場所などを分ける。検索中の矢印・Enter、通常のTab、Esc、起点への復帰を持つ。全体移動をDropdownMenuへ押し込まない。
- Dialogは判断が必要な処理、Popoverは対象の近くの補足、DropdownMenuは対象に対する操作。開閉とフォーカスの責務を分ける。
- Fieldは名前・説明・エラーを入力へ関連付ける。数値・日付・時刻の送信値と、表示上の補助は分ける。
- Grid、Flex、block、gap、margin-block-startの選択は[コンポーネント監査](component-audit.md#配置の一貫性)に従う。内部の役割名はルートから直下の関係で限定する。

## 提供する境界

`src/css`、`src/hono`、`src/controllers`を分ける。CSSと標準HTMLで使え、同じ構造をHono JSXでも出力する。必要なcontrollerを利用側のStimulus Applicationへ登録する。

業務の保存・認証・権限・通信・検索結果は利用アプリが持つ。カタログの試用処理をコンポーネントへ持ち込まない。追加候補と未提供機能は[コンポーネント監査](component-audit.md)を参照する。

確認は文字位置、状態と操作、狭幅と折り返しに分ける。静的検査、実ブラウザの寸法・操作、字形のピクセル検査、見た目の観察を別の証拠として扱う。
