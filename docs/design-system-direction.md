# 設計方針

Plyは予約・売上管理・CMS等で再利用する独立したデザインシステム。あずきブックスのアプリ実装ではない。出版社向けデザインの中央の作業面と上部のコンテキスト領域を継承し、Basecamp 5を軸に整える。

## 提供境界

- CSSと標準HTMLだけで利用できることを優先する。同じ構造をHono JSXで提供する。Reactは使わない。
- `src/css`、`src/hono`、`src/controllers`を分離し、Hono部品は個別ファイル、indexは再exportのみとする。
- JavaScriptは必要な操作に限る。stimulus-uiのcontrollerを利用側のStimulus Applicationへ登録し、自動起動や上流の再実装をしない。独自contract JSONは作らない。
- 保存・検索・業務状態は利用アプリの責務。カタログのデモ処理は`catalog`に置く。
- 書体はHiragino優先のシステムフォント。Webフォントは必須にしない。
- 現行の対象部品と高度な操作の範囲外は[部品一覧](component-coverage.md)を参照する。

## 見た目と操作

- 実製品の[画面資料](references/37signals-20260910/README.md)と実測を根拠にする。寸法の固定コピーではなく文字・余白の関係を扱う。参考製品の私的データを公開サンプルへ転載しない。
- 作業対象と主操作を近付ける。正常な下書きや常設説明を警告にしない。結果通知は操作に応じて出す。
- 一覧・編集・読む面の密度は用途で変える。中央の作業面と見出しの中央揃えを混同しない。
- ラベル、disabled、処理中、hover、focus、押下、復帰まで確認する。アイコンのみの操作にもアクセシブルな名前を付ける。
- 部品ごとに実物・状態・操作をユーザーと確認する。テスト成功をデザインの合意とみなさない。

## CSS規約

- 論理プロパティ、Grid優先、外側の間隔は親gap。必要な縦marginはmargin-block-startを使う。
- ネストは`&`付き、基本宣言を先に置く。コンテナクエリで部品幅へ対応する。
- レイヤー順は`layers.css`のみで宣言する。`@import`、`@scope`、BEM、`!important`は使わない。
- 状態・変種は意味を持つ`data-*`。ARIAやStimulus接続属性をCSSセレクタに使わない。
- 共有部品は内側、親は外側の配置を持つ。画面固有の上書きで部品の不足を補わない。
- 色は用途トークンを介する。文字に連動する寸法は相対値で扱い、狭幅・文字拡大・長文を確認する。
- 本文7:1、UI文字4.5:1、大きい文字・識別に必要な非テキスト3:1を検証基準とする。色だけで状態を伝えない。

検証方法と未確認環境は[README](../README.md#検証)を参照。公開・アプリ導入・ダークテーマは現作業の対象外。
